# DCS 짧은 이착륙 로그 분석

분석일: 2026-11-14. 사용자 지정: 첫 파일 P-51D, 마지막 파일 호넷. 로그의 aircraft 이름도 각각 P-51D/FA-18C_hornet으로 일치한다. 원본은 수정하지 않았다. 아래 시간은 별도 표시가 없으면 로깅 시작 후 경과 시간이다.

후속 구현(2026-11-14): 사용자 승인으로 센터 경로를 수정하고 High AoA를 선택 효과로 추가했다. 아래 내용은 분석 당시 진단이며, 현재 구현 결정은 CONTRACTS 최신 절과 MANUAL을 따른다.

## Shake: 이진 신호가 아니다

| 항목 | P-51D | 호넷 |

| 최소 / 최대 | 0 / 0.26102025 | 1.2674e-21 / 1.04426e-5 |
| 중앙값 / 95백분위 | 0.01111794 / 0.06984810 | 1.2499e-18 / 3.1230e-15 |
| 서로 다른 값 | 561개 | 1788개 |
| 기본 Power30, Full power amplitude1 환산 | 강도0–8,945표본 중402개만 양수 | 모든 표본 강도0 |

숫자는 소수로 계속 변한다. 따라서 0/1만 주는 신호라는 가설은 두 로그에서 반박된다. 반대로 실제 API 최대가 항상1이거나 두 기체가 같은 감도를 갖는다고도 결론낼 수 없다. 기본 Full power amplitude1은 설정값이지 이번 로그가 입증한 물리적 상한이 아니다.

P-51 최대 Shake는43.197초, 공중true→false 전환과 같은 표본이다.95백분위0.06985도 기본 강도로는 약2이므로 PWM을 끄더라도 대부분 작게 출력되는 이유가 있다. 시험 조정안은 P-51의 Full power amplitude를0.1–0.3 정도로 낮춰 비교하는 것이다. 이는 체감 시험용 제안이며 기본 스크립트/프로젝트는 이번 분석으로 변경하지 않았다.

호넷의 최대1.04426e-5는3.895초, 비공중/TAS0.0848인 표본에서 발생했다. 대부분 값은 그보다 여러 자릿수 더 작다. 여기에 무조건 큰 배수를 적용하면 극소 변화까지 증폭할 수 있다. 이번 로그만으로 호넷의 버핏이 없다고 하거나 API가 미지원이라고 단정하지 않는다. 충분한 공중 고받음각/고G/고속 조건은 이번 자료에 없다. 이 조건의 추가 비행 기록 후 Shake 감도를 정하는 편이 적절하다.

## Touchdown: 센터 경로 오류가 확인됨

두 기체의 실제 반환 경로는 다음과 같다.

```text
LoGetMechInfo.gear.main.left.rod
LoGetMechInfo.gear.main.right.rod
LoGetMechInfo.gear.nose.rod
```

현재 기본 touchdown.lua는 main에서 nose를 찾는다. 그러므로 센터 입력은 nil로 취급되어 출력하지 않는다. P-51의 테일기어 입력이 없는 문제가 아니라 원본 경로를 잘못 읽는 구현 문제다. 이전 조사 문서의 main.left/right/nose 표기도 잘못됐으며 실측 경로로 정정한다. 필요한 수정은 좌우는 gear.main, 센터는 gear.nose에서 읽는 것이다. 이번 요청은 정렬 변경과 로그 분석이므로 효과 코드는 변경하지 않았다.

- P-51: 지속 공중 구간은28.295–43.197초(전환 기준 약14.9초).43.197초에 right rod=0.06416,43.301초에 left=0.18473/right=0.61971/nose=0.24742다. 센터 신호도 착지104ms 뒤 분명하게 관측된다.43.751초에 다시 공중true,44.200초에 false로 바뀌며 그때 nose=0.07457이다. 여러 차례 접지·비접지 전환이 있어 바운스/재무장 검토에 유용하다. 실제 조종 상황 없이 모든 전환을 버그로 분류하지 않는다.
- 호넷: 공중true는71.456–71.787초, 전환 기준 약0.331초(시뮬레이션 시간0.327초),6표본이다.71.787초에 left=0.01755/right=0.01541, nose=0이다.72.674초에 nose=0.09287이 처음 나타난다. 메인 접지 뒤887ms이며 현재1500ms 착지 창 안이다. 다만 이 기록은 장시간 비행/정상 접근 착륙의 대표 자료가 아니다.
- 양쪽 모두 rod가 비공중 착지 구간에서0에서 상승하므로 이 두 기체의 이번 구간에서는 첫 상승을 감지하는 접근이 성립한다. 값이0–약0.88인 사실이 물리 단위·압축력·전 기체 동일 범위를 증명하지는 않는다.

## 다른 효과와 확장 여지

- G Load: 전체 Ny 범위는 P-51 0.441–2.663, 호넷0.718–1.456. 그러나 공중 표본의 최대는 각각1.455/0.885다. 기본 시작2G에 도달한 공중 표본은 없으므로 현재 G Load가 안 느껴져도 이 로그는 오류 증거가 아니다. P-51의2.663G는 착지 후 비공중 표본이다.
- Overspeed: 최대 TAS는49.51/80.90m/s, Mach는0.1643/0.2498. 기본250m/s/Mach0.85보다 낮고 경고 기본값도off다. 이 로그로 과속 경고 작동을 판정할 수 없다.
- 엔진 RPM: P-51 left23.07–101.60, right는 실제 반환값0. 호넷 좌우64.43–100.32. 양쪽 모두 시동/정지 구간을 포함하지 않는다. RPM90초과에서도 호넷 Shake는 최대2.09e-11이라, Shake가 항상 체감 가능한 엔진 진동을 대신한다고 볼 근거가 없다. 별도 RPM 대역별 진동은 가능한 확장 후보지만 공명 대역/진폭은 측정된 것이 아니며 사용자 정의 모델이어야 한다.
- 플랩: value는 P-51 0→0.4, 호넷 약0.598→0.667로 실제 변화한다. 반면 flaps.status는 둘 다0 고정이다. 기구 작동 진동을 검토한다면 value 변화량/지속시간이 유용하다. 자동/수동 작동 원인은 로그만으로 구분하지 않는다.
- 에어브레이크 value/status는 둘 다0 고정이라 작동 효과를 검증할 수 없다. 기어 value=1/status=0도 고정이어서 수납/전개 이벤트 근거는 없다.
- 세계속도 y, 가속도 xyz, 각속도 xyz는 실제 변하며 향후 착지 강도/운동 반응 후보의 입력이 된다. 각속도·가속도를 직접 힘/진동으로 등치하지 않는다. 고도·무장·기총은 현재 수집하지 않으므로 이번 로그로 평가 불가다.

우선순위는 센터 경로 수정 → P-51 Shake 감도 조정 비교 → 호넷 충분한 공중 기동 로그다. Thumps/별도 High AoA를 이 자료만으로 다시 추가할 근거는 없다. 기체별 프로젝트를 나누기보다 공통 입력과 기존 aircraft Override를 유지할 수 있다.
